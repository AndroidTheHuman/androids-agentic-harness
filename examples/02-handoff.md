## Judgment calls
- `tools/sessions.ts` must import `tools/sessionMeasures.ts`, and it runs under plain Node type stripping, which needs the `.ts` extension in the specifier; `tsc` rejects that without `allowImportingTsExtensions` → options: that tsconfig flag (compatible with `noEmit`), keep one file, or duplicate the functions → took the flag, one line in `tsconfig.json`. It is the first tool file to import another (`docMoves.ts` imports only `node:` modules). The tests import it without an extension.
- The brief moves `Entry`, `Block` and `isHumanPrompt` to `sessionMeasures.ts`; `Entry` refers to `Usage`, so `Usage` moved too, and gained `cache_creation` and `iterations`. `Entry` gained `effort` and `message.model`. I confirmed those field names on this session's own transcript (`effort`, `message.model`, `usage.cache_creation`, `usage.iterations`) before relying on them.
- `sessionTiming` counts overlapping shell calls once (union of the call-to-result spans); the brief's wording is "for each `Bash` or `PowerShell` `tool_use`, the time from…", which double-counts two parallel commands. The union is the honest wait; the brief's test and the two A.6 rows are unaffected. A test covers it.
- `carryLine` needs the two rarity versions for the `'version'` line, but its signature was `(outcome, genVersion, from)` → added an optional fourth argument `{ from, to }`, passed by `snapshotUpdate.ts` from the last table row and `RARITY_VERSION`. The alternative (a field on `carryCalibration`'s result) would have broken the existing `toEqual` assertions.
- `carryCalibration` checks the rarity version before the probe, so a version change that also moves the probe reports `'version'` (brief A.3: "it no longer folds into `'moved'`"). A test covers both.
- `carrySource` throws a `RangeError` if the last row's `carriedFrom` names a row that is not in the table; a validated table cannot do that, and returning `'none'` would hide it.
- In the carried path `--seed` and `--n` are unused, so they stay out of the recorded command, and the report is named by the verify seed (`calibration-g<g>-<verifySeed>.md`). A dry-run carry uses the placeholder reason `(dry run)` (it never reaches the table).
- Message texts the brief did not give: `genVersion <g> already has a row: running the full calibration`, `the table is empty: running the full calibration`, `Singular moved from genVersion <f>'s <a> to <b>: a new Singular runs the full calibration`, `--full: skipping the verify carry`, and `Calibration row written for genVersion <g>` after a carried write.
- `tests/calibration.test.ts` had `rarityVersion: 4` as "another version"; part B makes `RARITY_VERSION` 4, which would have turned that line into the same version → changed to `RARITY_VERSION + 1`, in the old and the new assertions.
- `docs/TOOLS.md` is edited directly, not proposed: brief §9 lists its `calibrate-rarity`, `snapshot:update` and `sessions` entries as part A's same-commit docs, and the active brief outranks CLAUDE.md's "never edit directly" for its own scope. The brief puts the success branch's first live run in a later package; I ran it because a dry run costs about 30 s and part B's session should not meet a wiring error in a 20-minute job.
